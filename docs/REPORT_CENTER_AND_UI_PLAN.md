# 诊疗档案快捷路径与前端美化方案（v2）

> 版本：v2.0 · 适用范围：当前仓库（Vue 3 + TypeScript + Element Plus + Django REST Framework）
> 相对 v1 的调整：**不再只做“检查报告中心”**。历史病历与检查报告同属“诊疗档案”，患者和医师都应从一级入口一键到达，并在同一页面内切换。

---

## 0. 摘要

- **现状**：患者要看历史病历，需「我的医疗 → 病历」；要看检查报告，需「我的医疗 → 检查报告」。医师要看某位患者的历史病历或报告，需先进入接诊工作区或诊疗资料，再跨页签、跨状态组查找，通常 4–5 次点击。
- **方案**：新增一级入口「诊疗档案」，页面内用两个页签承载**历史病历**与**检查报告**；患者直接看本人，医师先选患者；工作台、接诊工作区、检查队列、账单等上下文一键深链到对应患者、对应页签。
- **效果**：患者看历史病历或报告由 2–3 次点击降为 **1 次**；医师看某患者病历/报告由 4–5 次降为 **1–2 次**；病历与报告都采用“结论/诊断优先”的时间轴卡片，首屏即可阅读。
- **后端**：复用 `patients/{id}/clinical-history/` 与 `examinations/?patient=`；补充检查类型、报告状态筛选与发布时间排序，**不改表、不改权限模型**。
- **美化**：① 病历卡片“诊断优先”；② 报告卡片“结论优先”；③ 年月时间轴与骨架屏；④ A4 报告阅读器；⑤ 导航入口、动效与可访问性。

## 1. 现状盘点

| 角色 | 一级入口 | 历史病历位置 | 检查报告位置 |

### 1.4 问题清单

| 编号 | 问题 | 影响 |
| --- | --- | --- |
| P1 | 病历与报告分属两个三级页签 | 每次切换都要回到“我的医疗/诊疗资料” |
| P2 | 没有以患者为主键的聚合页 | 医师无法一屏看完某患者的病历 + 报告 |
| P3 | 病历列表按时间倒序但没有年月导航 | 历史跨度长时难以定位 |

| P6 | 患者侧栏“我的医疗”语义宽泛 | 病历与报告的心智入口不清晰 |

## 2. 目标

| 指标 | 现状 | 目标 |
| --- | --- | --- |
| 患者到达历史病历 | 1–2 次点击 | **1 次** |
| 患者到达检查报告 | 3 次点击 | **1 次** |

**设计原则**：一级直达、患者为主键、病历与报告同页、读写分离、URL 即状态。

## 3. 精简路径方案

### 3.1 信息架构

```text
患者：概览 / 诊疗档案★ / 个人医疗（预约就诊 · 我的医疗[处方|住院|智慧服务] · 我的费用）
医师：概览 / 诊疗档案★ / 诊疗工作（门诊工作 · 诊疗资料[病历|处方|医学检查|药品] · 住院工作）
```

- 「诊疗档案」`/patient/records`、`/doctor/records`，页内两个页签：
  - **历史病历**（默认）：已确认病历，按就诊时间倒序、年月分组。
  - **检查报告**：该患者全部检查报告，按发布时间倒序。
- 原「我的医疗 → 病历/检查报告」页签移除，旧地址自动跳转，避免重复入口。
- 「诊疗资料 → 病历/医学检查」保留，负责**书写、申请、录入、发布**；档案页负责**阅读**。

### 3.2 路由与 URL

| 路由 | 角色 | 说明 |
| --- | --- | --- |
| `/patient/records` | patient | 本人诊疗档案，默认历史病历 |
| `/patient/records?tab=reports` | patient | 直接打开检查报告页签 |
| `/doctor/records` | doctor | 患者选择 + 档案 |
| `/doctor/records?patient=12&tab=records` | doctor | 定位患者 + 历史病历 |
| `/doctor/records?patient=12&tab=reports` | doctor | 定位患者 + 检查报告 |
| `/doctor/records?patient=12&tab=reports&report=EX...` | doctor | 直接打开某份报告 |

**查询参数**

| 参数 | 说明 |
| --- | --- |
| `tab` | `records` / `reports` |
| `patient` | 医师视角患者 ID |
| `report` | 申请单号，打开报告阅读器 |
| `range` | 预留：`1y` / `3y` / `all` |
| `q` | 预留：关键词 |

### 3.3 患者视角

```text
我的诊疗档案
历史病历 12 份 · 检查报告 8 份 · 最近就诊 2025-03-18
[历史病历 12] [检查报告 8]
┌────────────────────────────────────────────────────┐
│ [日期范围] [诊断] [主诉/病历号] [查询] [重置]        │
├────────────────────────────────────────────────────┤
│ 2025 年 3 月                                        │
│ 18  偏头痛            已确认                        │
│     病历号 · 神经内科 · 张医师                       │
│     主诉：头痛三天         检查 1 · 处方 1 · 住院 0  │
│ 02  高血压复诊        已确认                        │
│ 2025 年 1 月                                        │
│ 12  上呼吸道感染      已确认                        │
└────────────────────────────────────────────────────┘
```

- 默认加载历史病历；点击“检查报告”页签切换，不重新进入页面。
- 病历卡片点击打开阅读器，展示主诉、现病史、既往史、体格检查、诊断、处理意见、关联检查与更正记录。
- 报告卡片点击打开 A4 阅读器，支持附件下载与打印。

### 3.4 医师视角

```text
患者诊疗档案
┌──────────────────┬────────────────────────────────────────────┐
│ [搜索姓名/患者号] │ 张明 · 男 42 岁 · P00012                    │
│ ● 张明 P00012     │ 过敏：青霉素 ｜ 慢病：高血压 ｜ 最近 03-18  │
│   李静 P00018     ├────────────────────────────────────────────┤
│   王强 P00031     │ [历史病历 12] [检查报告 8]                  │
│                  │ [日期范围] [诊断] [关键词] [查询]           │
│                  │ 2025-03-18 偏头痛  已确认  张医师  查看 →   │
│                  │ 2025-03-18 胸部 CT 已发布  阅读 →           │
└──────────────────┴────────────────────────────────────────────┘
```

- 左侧患者栏：`GET /patients/?search=`，仅返回与当前医师有预约关系的患者。
- 右侧患者信息带：姓名、性别、年龄、过敏史、既往病史、病历/报告份数、最近就诊。
- 历史病历与报告共用同一患者上下文；切换页签保留患者与筛选。
- 报告页可切换“全部/已发布/待发布”，待发布报告可跳回检查工作页补录。

### 3.5 三处上下文直达

| 入口 | 目标 | 参数 |
| --- | --- | --- |
| 工作台快捷操作（患者） | `/patient/records` | `tab=records/reports` |
| 工作台检查队列（医师） | `/doctor/records` | `patient=<id>&tab=reports` |
| 接诊工作区患者带 | `/doctor/records` | `patient=<id>&tab=records` |
| 接诊工作区“历次检查” | `/doctor/records` | `patient=<id>&tab=reports` |
| 检查管理患者姓名 | `/doctor/records` | `patient=<id>&tab=reports` |
| 账单检查费来源 | 患者/医师档案 | `report=<order_no>` 或 `tab=reports` |

## 4. 五条前端美化方案

> 以“诊疗档案”为主场景，组件与样式可复用到处方、账单、住院列表。

### 4.1 病历卡片“诊断优先”

- 左侧日期块：日号大字 + 年月，`IBM Plex Sans Condensed`，tabular-nums。
- 标题：诊断（16px/600）；副标题：病历号 · 科室 · 医师。
- 主诉一行截断；底部 chips：检查 N、处方 N、住院 N。
- 状态“已确认”绿色胶囊；hover 上浮 2px。
- 阅读器内“诊断”用 18px/600，主诉/现病史 14px/1.8。

**落点**：`components/archive/RecordTimeline.vue`、`RecordReader.vue`。

### 4.2 报告卡片“结论优先”

- 左侧 3px 状态色条（已发布绿 / 待发布琥珀 / 未录入灰）。
- 第一行：日期 + 项目名；第二行：结论两行截断；第三行：医师 · 科室 · 申请单号。
- 右侧：状态胶囊 + 附件类型 chips（PDF/影像/DICOM）。
- 未发布报告显示“报告尚未录入”，医师端给出补录入口。

**落点**：`components/reports/ReportCard.vue`。

### 4.3 年月时间轴 + 骨架屏

- 按年-月分组，分组头 sticky 于顶栏下方；滚动保持当前月份可见。
- 时间轴竖线与状态圆点，最近一条带淡色光晕。
- 加载时 3 张同尺寸骨架卡，避免布局跳动；空态用线性插画 + 行动文案。
- 分页保留 10 条/页，筛选器吸顶。

**落点**：`RecordTimeline.vue`、`ReportTimeline.vue`、`style.css`。

### 4.4 A4 报告阅读器

- 抽屉内白色纸张，页眉含患者、申请单、科室、医师、发布时间。
- 检查所见 14px/1.8，结论 18px/600；异常关键词浅红底高亮（仅文本规则，附免责声明）。
- 附件网格：类型图标 + 文件名 + 大小 + 下载。
- 底部固定操作条：上一份/下一份、打印、关闭；`@media print` 只输出纸张内容。

**落点**：`components/reports/ReportReader.vue`。

### 4.5 导航、动效与可访问性

- 一级「诊疗档案」入口；当前栏目胶囊高亮；折叠态只留图标。
- 患者端在病历/报告页签上显示份数 badge；医师端显示患者数/报告数。
- 统一 180ms 缓动；`prefers-reduced-motion` 关闭位移与 stagger。
- 状态“颜色 + 文本”双重编码；焦点可见；卡片支持 Enter/Space；触控目标 ≥44px。
- 移动端：患者栏折叠为顶部选择器；时间轴单列；阅读器全屏。

## 6. 验收清单

**功能**

- [ ] 患者侧栏「诊疗档案」一次点击进入，默认历史病历，可切检查报告。
- [ ] 医师侧栏「诊疗档案」可选择患者，查看其历史病历与全部报告。
- [ ] `?patient=`、`?tab=`、`?report=` 可刷新、可分享、可关闭。
- [ ] 病历阅读器展示主诉、现病史、既往史、检查、诊断、处理、关联检查、更正。
- [ ] 报告阅读器展示所见、结论、附件，可打印、可上一份/下一份。
- [ ] 工作台、接诊工作区、检查管理、账单均可一键定位患者档案。

**权限**

- [ ] 患者只能看本人已确认病历、已发布报告。
- [ ] 医师只能看有预约关系患者的病历与报告。
- [ ] 附件下载仍走鉴权接口。

**体验**

- [ ] 首屏骨架屏无布局跳动；空态/错误态有引导。
- [ ] 键盘可完成页签切换、打开/关闭阅读器。
- [ ] 减少动态效果下无位移动画。
- [ ] 375px 宽无横向溢出。
- [ ] `python manage.py check`、`python manage.py test healthcare`、`npm run build` 通过。
