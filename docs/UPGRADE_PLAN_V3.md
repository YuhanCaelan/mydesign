# 智慧医疗系统升级计划 v3（辩证版）

> 依据：一线医生建议 + 当前仓库实际实现 + 毕业设计的“简约、可演示、可解释”约束。
> 本文只定计划，不改代码；确认范围后再按 P0 → P1 实施。
> 核心判断：**保留临床逻辑正确的骨架，砍掉 HIS 级的复杂度，不照单全收。**

---

## 0. 结论摘要

8 条建议中：

| 结论 | 数量 | 建议编号 |
| --- | --- | --- |
| 直接采纳 | 4 条 | 1 排班归科室、3 急诊不预约、6 处方/执行/退费、8 疾病模板 |
| 改造后采纳 | 4 条 | 2 管理员只系统、4 接诊内开单、5 住院护士/病志/医嘱、7 二维码 |
| 完全不采纳 | 0 条 | — |

但有 5 个关键“不照做”：

1. **不新增 6–7 个角色**。用「5 个角色 + 科室事务员岗位」表达排班、住院处、收费、药房、医技，避免毕业设计角色爆炸。
2. **不新建 Encounter 大模型**。把 `Appointment` 扩展为“就诊主记录”，允许急诊无号源，避免全量重构。
3. **不把影像塞进二维码**。二维码只放**有时效的安全链接**，链接页再展示报告和片子。
4. **不保留“支付后自动发药”**。这是当前系统的逻辑错误，改为药房确认发药、发药时扣库存。
5. **不做完整 CPOE / 护理计划 / 日间手术排程 / PACS**。只做“门诊—急诊—住院—收费—执行—退费”的最小闭环。

建议交付顺序：

- **P0（答辩必做）**：角色/岗位、管理员收口、急诊 walk-in、接诊内开单、处方库存、处方/检查执行状态、退费、疾病模板、报告二维码。
- **P1（加分/完整）**：住院处办理、护士接诊、一个病志、长期/临时医嘱、处置目录、日间手术选项。
- **P2（明确不做）**：完整手术排程、麻醉、护理计划、医保、PACS/DICOM 阅片、部分退费、批次库存。

## 1. 评审原则

| 原则 | 说明 |
| --- | --- |
| 临床逻辑正确 | 谁能做、在哪个环节做、状态如何流转，必须符合真实医院的最小常识 |
| 毕业设计可完成 | 单人可在剩余时间内做完、能测试、能答辩 |
| 演示可解释 | 每个功能都能用一条业务链讲清楚，不堆孤立页面 |
| 单一事实来源 | 费用状态以账单为准，执行状态以医嘱为准，不重复存两份 |
| 权限最小化 | 医生不排班、护士不开药、管理员不办住院、患者不碰急诊预约 |
| 不做“假大空” | 不为了像 HIS 而做无人使用的模块 |

## 2. 八条建议逐条辩证评审

| # | 医生建议 | 临床合理性 | 当前系统差距 | 结论 | 简化落地 |
| --- | --- | --- | --- | --- | --- |
| 1 | 排班由科室专人排 | 正确，排班是科室运营行为 | 管理员可排全部；医生可排自己；无科室排班员 | **采纳** | 新增「科室事务员·排班岗」，只排本科室 |
| 2 | 管理员只管系统 | 正确，系统管理员不应碰业务 | 管理员菜单覆盖排班、住院、收费、检查 | **改造采纳** | 管理员管账号/字典/审计；业务交给岗位；保留兜底 |
| 3 | 急诊不能预约，不可预测 | 正确，急诊是 walk-in + 分诊 | `Appointment.slot` 必填，无急诊模型 | **采纳** | 扩展就诊类型，急诊无号源、现场登记、分诊队列 |
| 4 | 开药/住院/检查/处置都在接诊栏目 | 正确，减少医生跳转 | 处方/检查/住院分散在三个页面 | **改造采纳** | 接诊工作台统一“医嘱”页签，复用现有弹窗；日间手术先做选项 |
| 5 | 住院护士接诊，医护隔离，住院处办理，一个病志，长期/临时医嘱 | 正确，住院是医护分工 | 无护士角色；医生/管理员办理入院；无住院病志与医嘱 | **改造采纳（P1）** | 5 角色 + 一个住院病志 + 一张长期/临时医嘱表 |
| 6 | 处方在工作区，自动关联病志，支付后可查，执行科室确认，门诊退费 | 正确，订单全生命周期 | 支付后自动发药；无执行确认；无退费 | **采纳，并纠错** | 支付 ≠ 发药；药房/医技确认；退费仅全额、未执行 |
| 7 | 文字报告附二维码，二维码中有片子 | 方向正确，但技术表述错误 | 无二维码；附件需登录下载 | **改造采纳** | 二维码存安全链接，不存影像；链接页展示报告 + 图片 |
| 8 | 门诊疾病模板，快速拼接词 | 正确，能显著提速 | 病历全手写 | **采纳** | 模板 + 3–4 个变量（左右/轻重/病程），医生可改 |

### 2.1 排班：归科室，但不新增“排班员”角色

**现状**

- `ScheduleViewSet.perform_create`：管理员可建任意排班，医生可建本人排班，患者只读可约号源。
- 没有“科室排班员”，所以排班责任实际落在管理员和医生身上。

**建议做法**

- 新增角色 `STAFF`（科室事务员），用 `StaffProfile.station` 区分岗位：
  - `SCHEDULE` 排班岗
  - `ADMISSION` 住院处
  - `CASHIER` 收费/退费
  - `PHARMACY` 药房
  - `EXECUTION` 医技执行
- 排班岗只能管理**本人所属科室**的排班与号源；医生只读本人排班；患者只读可约号源；管理员只读或不可见。
- 保留现有 `generate_slots` 逻辑，不做复杂轮班、替班、号源规则引擎。

**验收**

- A 科室排班员不能修改 B 科室排班。
- 管理员的日常菜单里没有“创建排班”。
- 医生不能给自己加号源。

**不做**：多院区、跨科室借调、自动排班算法、停诊批量通知。

### 2.2 管理员只管系统：采纳 80%，保留字典维护

**现状**

- 管理员菜单覆盖人员、排班、医疗资源、住院、账单、审计。
- 业务接口大量使用 `role==ADMIN` 绕过科室范围。

**建议做法**

| 管理员保留 | 管理员交出 |
| --- | --- |
| 用户与角色 | 排班与号源 |
| 科室字典 | 门诊/急诊接诊 |
| 检查项目、药品目录 | 处方/检查/处置开单 |
| 审计日志 | 入院/出院办理 |
| 系统参数、演示数据重置 | 收费/退费/发药/执行确认 |

**为什么保留字典**：当前没有“药房主任/医技主任”岗位，药品与检查项目属于全院基础数据；如果强行下放，会再造一批角色。毕业设计里，管理员维护字典是合理折中。

**兜底**：`superuser` 仍可在后台处理异常，但前端不提供日常业务入口；演示时说明“这是应急兜底，非常规路径”。

**验收**

- 管理员登录后侧栏只有“系统管理”与“审计”。
- 管理员直接调用排班/入院/退费接口返回 403（superuser 除外）。
- 医生、护士、事务员按岗位看到不同工作台。

### 2.3 急诊：不能预约，改为现场登记 + 分诊

**现状**

- `Appointment.slot` 是必填外键，患者预约必须选号源。
- 没有急诊、分诊级别、到达时间。

**建议做法（不新建大模型）**

扩展 `Appointment` 为“就诊主记录”：

| 新字段 | 说明 |
| --- | --- |
| `visit_type` | `outpatient` 门诊 / `emergency` 急诊 |
| `source` | `online` 线上预约 / `window` 窗口 / `emergency` 急诊 |
| `slot` | 改为可空；门诊必须有号源，急诊必须为空 |
| `triage_level` | 1 濒危 / 2 危重 / 3 急症 / 4 非急症（急诊必填） |
| `arrived_at` | 到达时间，用于急诊排队 |
| `status` | 沿用 pending/in_progress/completed/cancelled/no_show；急诊 pending 即“候诊” |

**急诊流程**

```text
患者到院 → 护士/急诊台登记（无号源、分诊级别）→ 急诊医生队列
→ 接诊 → 病历/医嘱 → 完成或转住院
```

**患者端**

- 预约页不展示急诊科室，或展示提示“急诊请现场就诊，不支持预约”。
- 急诊登记由护士/事务员完成，患者不自助创建。

**影响面（必须同步改）**

- 所有 `appointment.slot.schedule.date` 的访问要加空值保护；
- 序列化器增加 `visit_date`，急诊回退到 `arrived_at/created_at`；
- 医生队列、工作台、统计、账单按就诊时间查询的地方要兼容无号源；
- 号源唯一约束不变，`slot=NULL` 不参与约束。

**不做**：新建 `Encounter` 模型、完整预检分诊评分、120 急救、急诊留观。

### 2.4 接诊内开单：统一工作台，但不做四套新页面

**现状**

- 处方在 `/doctor/clinical?tab=prescriptions`；
- 检查在 `/doctor/clinical?tab=examinations`；
- 住院在 `/doctor/inpatient`；
- 接诊工作区只能看，不能开单。

**建议做法**

- 把现有三个创建弹窗抽成可复用组件：
  - `PrescriptionForm`
  - `ExaminationForm`
  - `AdmissionRequestForm`
  - 新增 `ProcedureForm`
- 接诊工作区新增「医嘱」页签，内部四个子页签：

```text
本次病历 | 医嘱（处方 / 检查 / 处置 / 住院） | 历次就诊 | 历次检查
```

- 所有医嘱自动带当前 `record_id`，发送后自动关联病志，医生不用再选病历。
- 处方药品选择器显示**当前库存**；库存不足给黄色提示，但允许开具（库存可能在缴费前变化）。
- 新增「处置」目录与订单：
  - 类别：治疗、护理、小手术、日间手术；
  - 日间手术仅作为“处置项目选项 + 是否需预约时间”，不做手术间/麻醉/复苏排程。
- 独立页面保留为“科室执行/审计视图”，不再是医生主路径。

**验收**

- 医生在接诊工作区完成开处方、开检查、开处置、申请住院，全程不跳页。
- 处方选择药品时能看到库存。
- 医嘱自动关联当前病历，病历号在列表中可见。

**不做**：医嘱套餐（order set）、临床路径、合理用药审核、日间手术全流程。

### 2.5 住院：护士接诊 + 医护隔离 + 一个病志 + 长期/临时医嘱（P1）

**现状**

- 没有护士角色；
- 入院由医生/管理员创建并办理；
- 住院没有独立病志，只有 `admission_diagnosis` 和 `discharge_summary`；
- 没有长期/临时医嘱。

**建议做法**

**角色与分工**

| 角色 | 住院职责 |
| --- | --- |
| 医生 | 开入院申请、写住院病志、开长期/临时医嘱、办理出院（医疗决定） |
| 住院处事务员 | 分床、办理入院登记、出院结算 |
| 护士 | 接诊入院（生命体征、护理评估）、执行医嘱、记录执行时间 |
| 管理员 | 不参与 |

**流程**

```text
医生开入院申请（pending）
→ 住院处选床位、办理入院（admitted）
→ 护士接诊：测量生命体征、护理评估、确认到床（received）
→ 医生写住院病志 + 长期医嘱 + 临时医嘱
→ 护士执行医嘱并记录
→ 医生办理出院 → 住院处结算
```

**数据模型（最小）**

- `InpatientRecord`：与 `InpatientAdmission` 一对一，字段为主诉、现病史、既往史、查体、诊断、病程记录、出院小结。
- `InpatientOrder`：
  - `order_type`：`long` 长期 / `temp` 临时；
  - `category`：药品、护理、检查、处置、其他；
  - `content`、`dosage`、`frequency`、`start_at`、`stop_at`；
  - `status`：草稿、已提交、执行中、已完成、已停止、已取消；
  - `prescriber`、`executor`、`executed_at`、`execution_note`。
- `InpatientAdmission` 增加：`received_at`、`receiving_nurse`、`admission_staff`。

**权限隔离**

- 医生：可写病志、开/停医嘱；不能执行护理医嘱。
- 护士：可接诊、执行医嘱、写执行记录；不能改病志、不能开药。
- 住院处：只能分床/入院/出院结算；不能看病志细节（或只读摘要）。

**验收**

- 医生、护士、住院处三个账号进入住院模块看到不同页面。
- 一个住院只有一份病志。
- 长期医嘱与临时医嘱分开显示，护士执行后状态与执行人可见。

**不做**：护理计划、给药核对（MAR）、交接班、手术室、麻醉、住院药房发药、医保结算。

### 2.6 处方工作区、支付状态、执行确认、门诊退费

**现状问题**

- `BillingViewSet.pay` 在支付时**自动发药并扣库存**，这在真实流程中是错误的：支付只代表费用结清，发药应由药房确认。
- 检查 `start` 只允许医生/管理员，实际应由医技科室确认。
- 账单只有 `unpaid/paid/cancelled`，没有退费。
- 医生看不到“已缴费/待发药/已执行”的统一状态。

**建议做法**

**统一订单状态（不新建通用订单表）**

处方、检查、处置各自保留业务状态，序列化器统一输出：

| 派生状态 | 含义 | 来源 |
| --- | --- | --- |
| 待缴费 | 账单 unpaid | billing |
| 待执行/待发药 | 账单 paid，业务未执行 | billing + order |
| 执行中 | 已确认开始 | order |
| 已完成 | 已发药/已检查/已处置 | order |
| 已退费 | 退款完成 | refund |
| 已取消 | 作废/退费前取消 | order |

**处方**

```text
医生开具（待缴费）→ 患者缴费（待发药）→ 药房确认发药（已发药，扣库存）
```

- 去除“支付后自动发药”。
- 药房确认时校验库存并扣减；库存不足不允许发药。
- 医生工作区显示处方状态与缴费状态。

**检查/处置**

```text
医生开单（待缴费）→ 缴费（待执行）→ 医技/处置科室确认开始（执行中）
→ 完成（待报告/已完成）→ 报告发布
```

- 未缴费不能开始执行。
- 执行确认人记录 `executed_by/executed_at`。

**门诊退费**

- 新增 `RefundRecord`：账单、退款金额、原因、操作人、时间、退款单号。
- `BillingRecord` 增加 `REFUNDED` 状态。
- 仅收费岗可操作；仅“已缴费 + 未执行/未发药”的账单可全额退费。
- 退费后：账单置为已退费，关联处方/检查/处置置为已取消，写审计。
- 已发药/已执行的退费走人工流程，不在本期实现。

**验收**

- 支付后处方不会自动变成已发药。
- 药房确认后医生立即看到“已发药”。
- 未缴费的检查不能被医技确认开始。
- 收费员可搜索患者并完成退费；退费后医生看到已退费。

**不做**：部分退费、退药入库、跨院退费、医保退费。

### 2.7 报告二维码：二维码里不放片子，放安全链接

**先纠正一个技术点**：二维码容量只有几 KB，无法直接装下 CT/MRI 影像；正确做法是二维码编码一个**有时效的 URL**，扫码后打开报告页看文字和片子。

**建议做法**

- 新增 `ReportShareToken`：报告、随机 token、过期时间（7 天）、创建人、访问次数、是否撤销。
- 二维码内容：`{BASE_URL}/share/report/{token}`。
- 扫码页：
  - 报告文字：所见、结论、患者基本信息（脱敏）；
  - 附件：JPG/PNG 直接预览，PDF 内嵌，DICOM/NIfTI 提供下载；
  - 页脚注明“演示数据，仅限本次访问”。
- 二维码出现在：
  - 报告阅读器；
  - 打印版报告右上角；
  - 患者报告列表的“分享”按钮。
- 安全：token 过期/撤销即失效；记录扫码审计；不在 URL 中放患者身份证/手机号。

**不做**：把影像二进制塞进二维码、DICOM Web Viewer、公开患者检索。

### 2.8 门诊疾病模板：医生只填“左右/轻重”

**建议做法**

- 新增 `RecordTemplate`：
  - 科室、模板名、诊断；
  - 主诉、现病史、既往史、查体、处理意见；
  - 变量定义 JSON：`side`（左/右/双侧）、`severity`（轻/中/重）、`duration`（天数）、`location`；
  - 启用状态。
- 接诊工作区“本次病历”顶部增加「套用模板」：
  1. 选模板；
  2. 只填左右、轻重、病程等 2–4 个变量；
  3. 预览生成文本；
  4. 应用到病历，医生仍可自由修改。
- 种子模板 8 个：偏头痛、上呼吸道感染、急性胃肠炎、高血压复诊、膝关节骨关节炎、腰椎间盘突出、皮肤软组织感染、换药/拆线。
- 模板只生成草稿；已确认病历仍不可覆盖。

**验收**

- 选模板 + 填 2 个变量即可生成一份完整主诉/现病史/查体/处理。
- 医生可修改生成内容。
- 已确认病历不会被模板覆盖。

**不做**：LLM 生成、ICD 编码、诊断推荐、语音输入。

## 5. 状态机

### 5.1 就诊

```text
门诊：pending（待就诊）→ in_progress（就诊中）→ completed（已完成）
                     ↘ cancelled / no_show
急诊：pending（候诊）→ in_progress（接诊）→ completed（完成/转住院）
                     ↘ cancelled
```

### 5.2 处方

```text
待缴费 → 待发药（已支付）→ 已发药
   ↘ 作废        ↘ 退费（未发药）
```

### 5.3 检查/处置

```text
待缴费 → 待执行（已支付）→ 执行中 → 已完成 → 报告已发布
   ↘ 取消        ↘ 退费（未执行）
```

### 5.4 退费

```text
已缴费 + 未执行/未发药 → 退费申请 → 退费完成
已执行/已发药 → 不允许自助退费（转人工）
```

### 5.5 住院

```text
待入院 → 已入院（住院处）→ 护士接诊 → 住院中
→ 出院（医生）→ 住院处结算
↘ 取消
```

## 6. 页面与信息架构

### 6.1 医生

```text
工作台 / 接诊工作（门诊 + 急诊队列） / 诊疗档案 / 住院工作 / 我的排班（只读）
```

**接诊工作区**

```text
[患者信息带：姓名/过敏/慢病/急诊分诊级别]
[本次病历] [医嘱] [历次就诊] [历次检查]
            ├─ 处方（库存可见）
            ├─ 检查
            ├─ 处置（治疗/护理/小手术/日间手术）
            └─ 住院申请
```

- 每张医嘱卡片显示：待缴费 / 待执行 / 已完成 / 已退费。
- 发送后自动关联当前病历，不再选择病历。

### 6.2 护士

```text
护理工作台
├─ 急诊分诊/登记
├─ 住院接诊（待接诊列表、生命体征、护理评估）
├─ 医嘱执行（长期/临时、待执行/已执行）
└─ 床位概览（只读）
```

### 6.3 科室事务员（按岗位）

```text
排班岗：本科室排班、号源
住院处：待入院、分床、入院登记、出院结算
收费岗：待缴费、收费、退费（患者搜索）
药房岗：待发药队列、发药确认
医技岗：待执行检查/处置、执行确认
```

### 6.4 患者

```text
预约就诊（不含急诊） / 诊疗档案 / 我的费用 / 检查报告
```

- 急诊提示：“急诊请现场就诊，不支持预约”。
- 报告列表增加“分享二维码”。

### 6.5 管理员

```text
系统管理：用户与角色、科室字典、检查项目、药品目录、审计日志、系统参数
```

## 8. 验收场景（答辩演示）

### 场景 A：门诊全链路

```text
患者预约 → 医生接诊 → 套用“偏头痛”模板，填左右/轻重
→ 开处方（看到库存）→ 开检查 → 开处置
→ 患者缴费 → 药房确认发药 → 医技确认检查开始/完成
→ 医生看到“已发药/已执行” → 报告发布 → 二维码扫码看片子
→ 未执行项目退费
```

### 场景 B：急诊

```text
患者到院 → 护士登记（无号源、分诊 3 级）→ 急诊医生队列
→ 接诊 → 开检查/处置 → 需住院则开入院申请
```

### 场景 C：住院

```text
医生开入院申请 → 住院处选床/办理入院 → 护士接诊（生命体征）
→ 医生写住院病志 + 长期医嘱 + 临时医嘱
→ 护士执行并记录 → 医生办理出院 → 住院处结算
```

### 场景 D：权限

- 管理员打开排班/入院/退费接口 → 403。
- 排班岗 A 改 B 科室排班 → 403。
- 护士开处方 → 403。
- 医生执行护理医嘱 → 403。
- 患者访问未发布报告 → 403/过滤。

## 9. 风险与取舍

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 角色从 3 个变 5 个，权限代码散落 | 高 | 统一 `permissions.py` 辅助函数；所有接口用岗位/科室 scope；测试覆盖越权 |
| `slot` 可空影响所有日期查询 | 高 | 增加 `visit_date` 属性；全局搜索 `slot.schedule.date` 逐处兜底 |
| 状态既存又派生，出现不一致 | 中 | 费用状态只读账单；执行状态只读业务表；不在前端存状态 |
| 退费与库存/执行冲突 | 中 | 只允许“已缴费 + 未执行/未发药”全额退；其余转人工 |
| 住院模块范围膨胀 | 高 | P1 时间盒；只做病志 + 长期/临时医嘱 + 执行，不做护理计划 |
| 二维码泄露隐私 | 中 | token 过期/撤销、脱敏、审计、演示水印 |
| 管理员字典权限与“只管系统”冲突 | 低 | 明确字典属于系统基础数据；业务操作仍然交出 |
| 现有测试大量假设 admin 可操作 | 中 | 分批改测试；保留 superuser 兜底用例 |

| # | 决策 | 推荐 |

## 11. 建议的本期范围

如果只选一个范围开始实施，建议：

> **P0 全做，P1 做“住院处 + 护士接诊 + 一个病志 + 长期/临时医嘱”，P2 全部不做。**

这样既覆盖医生建议中的核心临床逻辑，又不会把毕业设计做成一个半成品 HIS。

6. 二维码；
7. 住院主线（P1）；
